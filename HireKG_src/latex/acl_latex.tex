\begin{abstract}
    Knowledge graphs (KGs) represent information as an interlinked network of entities, capturing the relational context that remains implicit in unstructured text. Most existing LLM-based text to KG converters follow an \emph{entity-first} pipeline: entities are extracted upfront, and relations are derived only between them. This design favors precision but systematically misses facts about a single entity, capping recall. We propose \textbf{HiReKG}, a high-recall extraction framework that reduces reliance on upfront entity extraction and introduces an object resolution module to keep the resulting triples cohesive. We evaluate HiReKG across three diverse datasets spanning general, scientific, and technical domains, using three LLM backbones. HiReKG improves recall over the strongest baseline by 18 percentage points on average (up to 29), with a precision trade-off of 2--9 points (5.7 on average), and recovers the single-entity facts that entity-first pipelines structurally miss.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Knowledge graphs (KGs) provide a structured representation of entities and the relations between them, enabling explicit multi-hop traversal that unstructured text alone does not support. Integrating KGs into retrieval-augmented generation and recommendation systems has been shown to substantially improve their ability to consolidate scattered context from source data \citep{llm-kg-emnlp-survey, recommendation_kg, text_summarization_kg}. These benefits have motivated a long line of work on automatic text-to-KG extraction, from classical OpenIE \citep{openie} to recent LLM-based approaches \citep{kg-llm-survey-arxiv}, all aimed at converting unstructured text into structured graphs that can be used by downstream NLP tasks.



Several LLM-based methods have been proposed for text-to-KG extraction, including KGGen \citep{kggen}, RAKG \citep{rakg}, GraphRAG \citep{graphrag_microsoft}, PiVe  \citep{pive}, and iText2KG \citep{itext2kg}. Despite differences in their specific designs, all of these methods share a common pattern: entities are first extracted from the source text, and relations are then derived only between pairs of those extracted entities. We refer to this shared pattern as the \emph{entity-first} pipeline. 


The \emph{entity-first} design favors precision because every relation is grounded against an explicit entity set, but it carries a structural consequence. Any entity missed in the first stage is lost entirely, since no relation involving it can be recovered later. Equally, any fact in source text that describes a single entity in isolation, without a second entity to pair with, falls outside the relation-extraction step by construction. Together, these two failure modes produce a systematic coverage gap, particularly on facts that involve a single entity. To address this gap, we propose \textbf{HiReKG}, a high-recall text-to-KG extraction framework that reduces reliance on upfront entity extraction, allowing the LLM to surface facts about each entity directly from the source text, including those that do not pair with a second entity. However, removing the entity-pair constraint can leave the graph disconnected and repetitive, with the same entity scattered across multiple unlinked mentions. HiReKG resolves this with an object resolution module that restores connectivity by linking these mentions into shared graph nodes.

The main contributions of this paper are as follows:
\begin{itemize}
    \item \textbf{HiReKG}, a high-recall text-to-KG extraction framework that, unlike the dominant entity-first paradigm, recovers single-entity facts while preserving competitive precision.
    \item A single-entity vs.\ multi-entity decomposition showing that entity-first baselines systematically under-recover single-entity facts, a gap that HiReKG largely closes.
\end{itemize}




\section{HiReKG}
\label{sec:method}
HiReKG extracts a knowledge graph from plain text in three stages: subject extraction, property extraction, and object resolution, followed by the refinement stage of \citet{kggen}. The source document is first split into chunks, and each stage runs over all chunks before the next begins. Figure~\ref{fig:pipeline} contrasts HiReKG with the entity-first paradigm: subject extraction mirrors the entity-extraction step of prior pipelines, but HiReKG then decouples property extraction from the entity-pair anchor and adds an object resolution step that restores graph connectivity before refinement. A full end-to-end run on a sample paragraph is provided in Appendix~\ref{app:walkthrough}.

\subsection{Subject Extraction}
\label{sec:method-subject}
Following prior LLM-based extractors \citep{kggen, rakg}, we prompt an LLM on each chunk to identify the set of entities mentioned in the source document. Each entity in this set serves as a \emph{subject} around which information is later organized.


\subsection{Property Extraction}
\label{sec:method-property}
For each chunk, the LLM is prompted to gather all information about the set of subjects identified in Section~\ref{sec:method-subject}. The output is a set of \emph{triples} \texttt{(subject, relation, object)}, where the subject is one of the extracted entities, the relation is a free-form predicate, and the object is a natural-language phrase describing a property, attribute, or related entity. Crucially, and unlike entity-first methods, the object is not constrained to be another extracted entity: it may be a date, a quantity, a descriptive clause, or a phrase that itself references one or more entities.

This relaxation is what lets HiReKG recover single-entity facts. A statement such as ``The Eiffel Tower is 330 metres tall'' yields the triple \texttt{(Eiffel Tower, height, 330 metres)} keyed on a single subject, with no second entity required. 

The trade-off is structural. When an object is a phrase that references other entities, those entities remain trapped inside the object string rather than appearing as proper graph nodes; for instance, ``Marie Curie won the Nobel Prize in Physics and the Nobel Prize in Chemistry'' is extracted as a single triple whose object embeds two prize entities that should each be a node in their own right. As a result, the graph initially fragments into per-subject \emph{stars}, as shown in the left pane of Figure~\ref{fig:object-resolution}. Object resolution repairs this fragmentation.

\subsection{Object Resolution}
\label{sec:method-resolution}
Object resolution rewrites raw triples so that any extracted entity appearing inside an object string becomes a proper object (Figure~\ref{fig:object-resolution}). For each raw triple, the object is normalized (lowercased, lemmatized, with determiners stripped) and matched against the extracted entity set using word-boundary string matching; triples with no match are forwarded unchanged. Triples with one embedded entity can be split apart by a fixed rule, while triples with multiple embedded entities can be split in several different ways and need the LLM to choose. We therefore use two repair procedures.
\paragraph{Single embedded entity.} The object is tokenized and decomposed into a \emph{prefix} (text before the entity), the entity span, and a \emph{suffix} (text after the entity). In the common case, only a prefix is present: the prefix is folded into the relation and the entity becomes the new object, producing $(s, r', e)$ where $r'$ is the relation with the prefix appended. This deterministic path handles the majority of single-entity cases without an LLM call. When a suffix is present, an LLM rewrites the triple so that the entity becomes the object and any remaining content is folded into the relation.
\paragraph{Multiple embedded entities.} The LLM is prompted with the original triple, the list of detected entities, and a structured analysis of each entity's surrounding context. It selects one of three decomposition strategies and emits a set of triples in which every embedded entity appears as a proper object. \textsc{Hub} handles parallel lists, such as the two-Nobel-Prize triple from Section~\ref{sec:method-property}; \textsc{Chain} handles sequential connectives; and \textsc{Nested} handles hierarchical phrasing.

All LLM-rewritten triples are validated for entity coverage and field completeness, reverting to the original on failure. By promoting embedded entities to graph nodes, object resolution converts the per-subject \emph{stars} of Section~\ref{sec:method-property} into a connected graph without imposing the entity-first constraint at extraction time. Worked examples for each pattern (single-entity, \textsc{Hub}, \textsc{Chain}, \textsc{Nested}) appear in Appendix~\ref{app:obj-res-examples}.

\subsection{Datasets}
\label{sec:datasets}
We evaluate on three datasets spanning distinct text styles. \textbf{MINE-1} \citep{kggen} provides 100 LLM-generated documents paired with manually verified atomic facts that serve as a recall ground truth. \textbf{SciERC} \citep{scierc} contains 100 scientific abstracts    annotated with entities and relations, representing dense technical prose. \textbf{Re-DocRED} \citep{redocred} is a cleaned version of DocRED \citep{docred} built from Wikipedia documents; we use the 15-document subset introduced by \citet{lkd-kgc}. All three datasets have been used in recent text-to-KG work \citep{graphjudge, rakg}, enabling direct comparison with prior results.



\subsection{Baselines and Metrics}
\label{sec:baselines}
\paragraph{Baselines.} We compare HiReKG against \textbf{KGGen} \citep{kggen} and \textbf{RAKG} \citep{rakg}, the two strongest representatives of the entity-first paradigm.
\paragraph{Metrics.} We report recall and precision via two LLM-as-judge metrics. \textbf{MINE Score} \citep{kggen} (recall) is the ratio of ground truth atomic facts that can be inferred from the extracted graph. \textbf{Faithfulness Score} (precision), adapted from RAG evaluation \citep{ragas}, measures the fraction of extracted triples supported by the source text. As a supporting measure, the deterministic \textbf{Unique Information Ratio (UIR)} captures redundancy as the fraction of non-overlapping triples; UIR results are reported in Appendix~\ref{app:uir}. Full prompts and configurations of all metrics are in Appendix~\ref{app:metrics}.
\paragraph{Models.} We run each method with three LLM backbones: \textbf{GPT-4o} \citep{gpt4o}, \textbf{Qwen3-14B} \citep{qwen3_14b}, and \textbf{Qwen3-8B} \citep{qwen3_8b}, spanning one flagship closed model and two open-weight models of different scales. Exact versions and hyperparameters are listed in Appendix~\ref{app:hardware}.



\subsection{Single-Entity Decomposition Results}
\label{sec:single-entity}
Our central hypothesis is that entity-first pipelines structurally under-recover facts that describe a single entity in isolation. To test this directly, we classify each atomic fact in the ground truth as \emph{single-entity} (mentioning one of the document's entities) or \emph{multi-entity} (connecting two or more), and report the MINE Score on each subset.\footnote{Classification uses ground-truth entity annotations on SciERC and Re-DocRED, and GPT-5~\citep{gpt5} on MINE-1 with a spaCy NER sanity check (76.8\% agreement); see Appendix~\ref{app:datasets}.}

Table~\ref{tab:recall} reports the decomposition, and the pattern is consistent with the hypothesis. KGGen and RAKG show a systematic single-entity deficit: their single-entity score is lower than their multi-entity score in 14 of 18 configurations, with average gaps of $-7.4$ pp and $-11.0$ pp respectively. The deficit is sharpest on Re-DocRED, where both baselines collapse to single-entity scores of $35.7\%$ and $37.5\%$ with GPT-4o while remaining above $53\%$ on multi-entity facts. HiReKG, in contrast, is near-symmetric (average gap $-2.4$ pp), and its absolute single-entity score exceeds the strongest baseline by $+24.1$ pp on average (up to $+42.9$ pp), with the largest gains precisely where the baselines collapse. The recall advantage is therefore not a generic uplift: it is concentrated on the class of facts the entity-first design undercaptures.



\subsection{MINE and Faithfulness Scores}
\label{sec:main-results}
Tables~\ref{tab:recall} and~\ref{tab:faith} report overall recall and precision across the nine LLM--dataset configurations. HiReKG improves recall over the strongest baseline in every configuration, by $+4.1$ to $+29.5$ pp absolute ($+6.4\%$ to $+55.7\%$ relative). The gain is largest on MINE-1 and Re-DocRED with the mid-scale Qwen3-14B, and remains substantial on GPT-4o where the baselines are already at their strongest. RAKG and KGGen alternate as the stronger baseline depending on dataset and model, but HiReKG outperforms both in every cell.

On Faithfulness, KGGen retains the highest score in every configuration, consistent with its strict entity-pair anchoring. HiReKG trails KGGen by $2.1$ to $9.2$ pp, with the gap narrowing on the open-weight models ($2.1$ to $7.3$ pp). HiReKG substantially outperforms RAKG, whose Faithfulness falls as low as $57.4\%$ on MINE-1 with GPT-4o. HiReKG's precision therefore sits between the two baselines while recovering the bulk of KGGen's recall gap, a net improvement for downstream tasks that value coverage.



\subsection{Redundancy and Cost}
\label{sec:cost-redundancy}
We further measure graph redundancy via UIR and inference cost in total tokens per document. HiReKG achieves the highest overall UIR ($0.71$ vs.\ $0.68$ for KGGen and $0.59$ for RAKG), producing graphs that are less redundant per triple, a property that matters for downstream tasks~\citep{redundanyinkg}. The cost overhead is bounded: HiReKG uses roughly $3\times$ the tokens of KGGen but less than half of RAKG. The additional tokens connect the scattered triples from property extraction, driving HiReKG's recall and UIR gains. Detailed breakdowns are in Appendices~\ref{app:uir},~\ref{app:cost}, and~\ref{app:obj-res}.

\section{Conclusion}
\label{sec:conclusion}
We presented HiReKG, a text-to-KG extraction framework that decouples property extraction from entity-pair anchoring and restores graph connectivity through a dedicated object resolution module. Across nine LLM--dataset configurations, HiReKG achieves the highest recall in every cell while keeping precision within a narrow margin of the strongest entity-first baseline. A single-entity decomposition closes the loop: the systematic deficit on facts that describe a single entity in isolation, long latent in entity-first pipelines, is empirically identified and substantially recovered by HiReKG. The result demonstrates that the coverage ceiling of current text-to-KG systems is not intrinsic to the task but is an artifact of design choices that can be relaxed without sacrificing graph quality.



\section{Limitations}

\paragraph{Downstream evaluation.} We evaluate HiReKG on intrinsic KG-quality metrics (recall, precision, redundancy) rather than on downstream tasks such as graph-based retrieval-augmented generation. A fair downstream comparison would require choosing retrieval methods per domain, which is a separate study in itself.

\paragraph{No multi-seed variance.} The scores in Tables~\ref{tab:recall} and~\ref{tab:faith} are single-run point estimates; multi-seed confidence intervals were not feasible under our compute and API budget. We instead report per-document standard deviations in Appendix~\ref{app:variance}, which capture LLM-judge variability across documents within each configuration.

\paragraph{Single-document scope.} HiReKG produces one KG per input document. Multi-document KG construction is a harder, distinct problem that requires cross-document entity linking and conflict resolution between sources, and is outside the scope of this work.

\paragraph{Potential risks.}
HiReKG outputs are LLM-generated and may contain hallucinated triples; Faithfulness quantifies but does not eliminate this. MINE and Faithfulness also rely on LLM judges and inherit their biases. Downstream systems should verify triples against the source text before treating the graph as authoritative.

\stageblock{Stage 5 --- Refinement (canonicalization, 24 entities)}

Refinement canonicalizes surface variants in the entity set. On this trace, the plural form \texttt{eggs} is folded into the singular \texttt{egg}, and the redundant second occurrence of \texttt{host plants} is removed, reducing the entity set from 25 to 24. Triples referencing the dropped surface forms are rewritten against the canonical entity, yielding the final knowledge graph.%



A brief commentary on what each stage contributes. Subject extraction recovers the entities that anchor the document. Property extraction lifts the entity-pair constraint, allowing free-form objects: this is what preserves single-entity facts such as \texttt{(larva, grows, rapidly)} and \texttt{(adult butterfly, live, a few days to several weeks)}, which entity-first pipelines drop by construction. The detection step then partitions raw triples into a clean set, a single-embedded-entity set that the prefix/suffix rule resolves deterministically, and a multi-embedded-entity set routed to the LLM for \textsc{Hub}, \textsc{Chain}, or \textsc{Nested} decomposition. Object resolution applies these branches: a single raw triple about the four life-cycle stages becomes four \texttt{has stage} edges, and the appositive \texttt{a tubular mouthpart called a proboscis} becomes a two-hop chain. Refinement performs surface-form deduplication without changing semantics.

\section{Evaluation Prompts and Judge Configuration}
\label{app:metrics}

Both MINE Score and Faithfulness Score are LLM-as-judge metrics. This appendix provides the verbatim prompts and the judge configuration used in all reported experiments.

\paragraph{Judge models.} To avoid same-model bias between extractor and judge, the judge is matched by tier: \textbf{GPT-5}~\citep{gpt5} judges all knowledge graphs extracted by GPT-4o, and \textbf{Qwen3-32B}~\citep{qwen3_32b_fp8} judges all knowledge graphs extracted by Qwen3-14B and Qwen3-8B. The judge model is held fixed across HiReKG and both baselines within each tier, so the comparison is symmetric. Both judges are queried at high reasoning effort, with structured JSON output, and outputs that fail to parse as valid JSON are counted as judge errors and excluded from the denominator (see scoring formulas below).

\paragraph{MINE Score (recall).} For each ground-truth atomic fact, top-$k{=}8$ KG nodes are retrieved by cosine similarity over \texttt{all-MiniLM-L6-v2} embeddings of the fact against each node name. Each retrieved node is expanded by a two-hop traversal over outgoing and incoming edges, and every traversed edge $(s, r, o)$ is serialized as the sentence \texttt{"$s$ $r$ $o$."} (or \texttt{"$o$ $r$ $s$."} for incoming edges). The resulting sentences are joined with single spaces into a flat context blob. We use the canonical retrieval routine from \texttt{kg-gen}~\citep{kggen} unchanged across all methods. The judge is then prompted with the context blob and the atomic fact:

\stageblock{MINE Score judge prompt (system + user)}{%
\textit{System:} You are an evaluator. Determine whether the provided context contains the information stated in the given correct answer. Think step-by-step internally, then respond with valid JSON of the form \texttt{\{"reasoning": "<brief reasoning>", "evaluation": 0 | 1\}}. Rules: \texttt{evaluation = 1} if the context contains (supports) the correct answer, \texttt{0} otherwise. Evaluate on information content, not exact wording; paraphrases are fine. If the context is empty or irrelevant, return \texttt{0}. Output ONLY the JSON object, no code fences, no extra keys.\par
\textit{User:} \texttt{Context:\textbackslash n---\textbackslash n\{context\}\textbackslash n---\textbackslash n\textbackslash nCorrect answer:\textbackslash n---\textbackslash n\{correct\_answer\}\textbackslash n---\textbackslash n\textbackslash nDoes the context contain the information stated in the correct answer? Respond with JSON.}%
}

\noindent The per-document MINE Score is the fraction of facts judged \texttt{evaluation = 1}, averaged across documents.

\paragraph{Faithfulness Score (precision).} For each predicted triple $(s, r, o)$, a verbalization LLM converts the triple into a single self-contained English sentence (the \emph{statement}) using the prompt below. The same retrieval embedder \texttt{all-MiniLM-L6-v2} is then used to retrieve the top-$k{=}5$ most similar chunks of the source document as context. The judge receives the context and the statement and emits a \texttt{SUPPORTED}/\texttt{NOT\_SUPPORTED} verdict with a required verbatim supporting span:

\stageblock{Faithfulness Score verbalization prompt}{%
You convert a structured knowledge-graph triple (subject, predicate, object) into ONE self-contained English sentence that asserts the same fact.\par
\smallskip
\textit{Strict rules:} Produce exactly ONE declarative sentence with no preamble. Preserve the subject and object strings verbatim; do not paraphrase, expand, abbreviate, change capitalization, or substitute synonyms. The predicate may be lightly inflected (tense, articles, auxiliary verbs) only as needed to form a grammatical sentence. Do not introduce information not present in the triple. Do not use pronouns; refer to the subject and object by their exact strings. Output only the sentence.\par
\smallskip
\textit{Input:} \texttt{subject: \{subject\}; predicate: \{predicate\}; object: \{object\}}.%
}

\stageblock{Faithfulness Score judge prompt}{%
You are an entailment judge for knowledge-graph faithfulness evaluation. Given a SOURCE TEXT and a STATEMENT (verbalized from a predicted KG triple), decide whether the source text SUPPORTS the statement.\par
\smallskip
\textit{Verdicts:} \texttt{SUPPORTED} if the source text explicitly entails the statement (paraphrases count, but the same proposition must be expressible from the source's wording). \texttt{NOT\_SUPPORTED} if the source either contradicts the statement or is simply silent on it.\par
\smallskip
\textit{Strict rules:} Use ONLY the source text; ignore world knowledge and prior beliefs. Before deciding, attempt to identify a verbatim span from the source. If a span supports or contradicts the statement, copy it exactly; if the source is silent, set \texttt{supporting\_span} to \texttt{null}. The \texttt{reasoning} field (1--2 sentences) must explicitly relate the cited span (or its absence) to the statement. Output a single strict JSON object with keys \texttt{supporting\_span}, \texttt{reasoning}, \texttt{verdict} in that order. No code fences, no extra keys.%
}

\noindent The verbalizer runs on GPT-5-mini (closed tier) or Qwen3-32B (open tier) at low reasoning effort. The per-document Faithfulness Score is
\[
\text{Faithfulness} = \frac{n_{\text{supported}}}{n_{\text{total}} - n_{\text{malformed}} - n_{\text{judge\_errors}}},
\]
where $n_{\text{malformed}}$ counts triples whose verbalization failed schema validation and $n_{\text{judge\_errors}}$ counts judge outputs that failed JSON parsing. The dataset score is the mean of per-document scores.

\section{Unique Information Ratio}
\label{app:uir}

\paragraph{Metric.} The Unique Information Ratio (UIR) measures redundancy among predicted triples. Each triple $(s, r, o)$ is verbalized into a short sentence and embedded with \texttt{all-MiniLM-L6-v2}; pairs whose embedding similarity exceeds a threshold are clustered together, so that paraphrased triples expressing the same fact collapse into a single cluster. UIR is defined as
\[
\mathrm{UIR} = \frac{n_{\text{clusters}}}{n_{\text{triples}}},
\]
where higher values indicate that every triple contributes a distinct fact and lower values indicate redundancy. A graph in which every triple is unique has $\mathrm{UIR}=1.0$; a graph whose triples collapse into half as many distinct facts has $\mathrm{UIR}=0.5$.

\section{Single/Multi-Entity Classification}
\label{app:datasets}

The single-entity decomposition reported in Section~\ref{sec:single-entity} requires classifying every atomic fact in the recall ground truth as \emph{single-entity} (mentioning exactly one of the document's entities) or \emph{multi-entity} (mentioning two or more). The classifier differs by dataset because the available annotations differ.

\paragraph{SciERC and Re-DocRED.} Both datasets provide gold-annotated entity sets for each document. We apply deterministic string matching: each annotated entity is searched in the fact text with case-insensitive, whitespace-normalized, word-boundary-aware regex matching. Overlapping matches are deduplicated by retaining only the longest non-overlapping span, so that ``Microsoft Windows'' is not double-counted as ``Microsoft'' plus ``Windows''. A fact with one matched entity is labeled single-entity, with two or more matched entities multi-entity, and with zero matched entities ambiguous (the latter folded into multi-entity for analysis, matching the strictest possible single-entity definition).

\paragraph{MINE-1.} MINE-1 atomic facts do not come with annotated entity sets, so deterministic matching is not available. We classify each fact with GPT-5~\citep{gpt5} using a zero-shot prompt that asks the model to count the entities mentioned in the fact and emit one of \texttt{single-entity}, \texttt{multiple-entity}, or \texttt{ambiguous}. The prompt instructs GPT-5 to treat both proper nouns (e.g., ``Marie Curie'') and common-noun entities (e.g., ``butterfly'', ``chrysalis'') as entities, since MINE-1's LLM-generated explanatory prose contains few proper nouns. Ambiguous facts are again folded into multi-entity for analysis.

\paragraph{Validation against spaCy NER.} We validated the GPT-5 labels against spaCy NER (\texttt{en\_core\_web\_sm}), applying the same count-based classification rule to spaCy's entity spans. Across $1{,}500$ MINE-1 facts, GPT-5 and spaCy agreed on $76.8\%$ of labels (Cohen's $\kappa = 0.32$). The disagreement is asymmetric and concentrated where expected: spaCy systematically under-recognizes common-noun entities that off-the-shelf NER models are not trained to tag (``butterfly'', ``caterpillar'', ``chrysalis''), but agrees strongly with GPT-5 on facts containing proper nouns ($P{=}0.84$, $R{=}0.86$ on multi-entity facts). Our analysis uses the GPT-5 labels because they more accurately reflect MINE-1's actual entity structure; the residual disagreement on common-noun-heavy facts is the expected behavior of off-the-shelf NER rather than a labeling error.

SciERC is the most balanced of the three; MINE-1 and Re-DocRED are similarly skewed toward multi-entity, with single-entity facts forming roughly a quarter of each dataset. Re-DocRED's smaller absolute count ($56$ single-entity facts) reflects its 15-document scope and is sufficient for the per-cell averages reported in Section~\ref{sec:single-entity}.

\section{Per-Document Variance}
\label{app:variance}



Table~\ref{tab:variance} reports the per-document mean and standard deviation of MINE Score for each method, dataset, and extractor LLM. Each value is computed across the documents in the dataset's evaluation split, after running the full extraction and judging pipeline once per document.


\paragraph{Variance reduction.} Beyond the recall gains reported in the main paper, HiReKG also exhibits consistently lower per-document variance than either baseline. Averaged across the nine configurations, HiReKG's standard deviation is $13.0$, compared with $16.7$ for RAKG and $20.3$ for KGGen. The reduction is largest on MINE-1 with GPT-4o ($-8.9$ std relative to the strongest baseline) and holds in 8 of 9 configurations; the single exception is Re-DocRED with Qwen3-8B ($+3.1$ std), which is also the only configuration where HiReKG's mean score does not exceed the strongest baseline by a wide margin. Lower variance means HiReKG's recall advantage is distributed across documents rather than driven by a small number of high-scoring outliers, which makes the headline gains in Section~\ref{sec:main-results} more reliable as a per-document expectation.

\paragraph{What is and is not measured.} The standard deviations above capture variation \emph{across documents} within a single run of each pipeline. They do not capture variation \emph{across LLM rollouts} on the same document, which would require multi-seed runs that were not feasible under our compute budget. We note this as a limitation.
